# 仅无损模式怎么用？换容器不降画质，压不到直说

- slug: video-file-compressor-lossless
- h1: 视频文件压缩教程：仅无损模式与「压不到」的诚实行为
- 摘要: 仅无损只换容器重封装成 mp4，视频流指纹前后一致，绝不偷偷降画质；压不到目标时不出片并告诉你最小能到多少，几十条批量也有实测兜底。
- 关键词: 视频无损压缩, mkv 转 mp4, 仅换容器, 视频压缩 不损画质
- 排序: 3

## 导语

按体积压缩必然重编码。有些片子你一点细节都不想丢——那用「仅无损」：它只把 mkv、avi、ts 等容器重新封装成兼容性最好的 mp4，画面数据一个字节不动。这篇也讲清楚：程序什么时候会拒绝出片，以及为什么这是优点。

## 开始之前

- 已打开视频文件压缩，理解「按体积压缩必然重编码」这个前提
- 手里有 mkv / avi / ts 等容器想统一成 mp4 的片子，或设计上不能有损的素材
- 明确目标体积只是「上限」，不是「必须精确达到」

## 操作步骤

### 1. 什么时候用仅无损

想统一容器格式（mkv/avi/ts → mp4）、或素材不能有任何重编码时用它。源片体积本来就在目标以内时，普通模式也会原样复制不重编码，效果一样。

### 2. 勾选「仅无损」

勾上后尺寸设置行自动锁灰并写明「仅无损不改尺寸」——换容器是原样搬画面数据，改尺寸必须重编码，两者互斥，程序不会让你误以为两个都开了。

### 3. 认清它能省多少

仅无损省的是容器开销：实测 2.07MB 的 mkv 换成 mp4 后 2.02MB，视频流 MD5 前后一致。指望它省一半体积，说明里会直说做不到——「仅无损只能省容器开销，要更小必须重编码」。

### 4. 理解「未达标，不出片」

降到画质地板仍压不进目标时，程序不出片，说明里给出「最小可达约 X MB」和建议：调高目标、改小尺寸（取消仅无损后）、或先把片子剪短。极端例子：指定尺寸加 51KB 目标，会提示「51KB 连音频轨道本身都放不下」。不交付糊片，比标个假「达标」诚实。

### 5. 用三处界面自己核对

「说明」列逐条写码率、分辨率、音频处理方式；双击任意一行看完整披露（是否重编码、码率前后、帧率、编码器、耗时等 11 个字段）；状态栏常驻「本次 0 次联网」。

## 常见问题

### Q: 仅无损能把 2GB 压到 500MB 吗？

A: 不能，它不改画面数据。大体积压缩请取消仅无损、走正常的重编码流程，程序会在画质地板内尽量保细节。

### Q: 批量几十条会不会中途出错、互相覆盖？

A: 压力实测 100 条短片 100/100 达标、100 个结果全不同名，平均每条约 1.1 秒，主进程内存峰值仅 33MB；同名自动加序号，绝不覆盖。

### Q: 手机竖拍、无音轨的片子会出问题吗？

A: 不会。竖拍按你看到的方向处理（720×1280 压完仍是竖的 480×854）；无音轨的片子照实写「无音轨」，不编造音频字段。

### Q: 压缩中途取消会留下半截文件吗？

A: 不会。取消会真的掐掉正在跑的编码并收尾，实测长片跑到 40% 取消，out 里 0 个文件、源片完好、报告写「已取消」，之后可以重跑。

## 进阶技巧

- 源片已达标（体积小于目标）时不用任何设置，程序自动原样复制，零等待。
- 90 秒 1080p 大文件（93.6MB → 目标 6MB）实测出片 5.72MB、时长一分不差。
- 编码速度约 0.3–0.4 倍实时是纯 CPU 的代价，换来的是装完就能用、不挑显卡。
